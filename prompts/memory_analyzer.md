# Meeting Memory 分析器

## 任务

从原材料中提取与组会生存直接相关的真实信息，构建 Meeting Memory。

重点不是整理“导师完整人生画像”，而是整理：

* 用户在什么场景下最容易慌
* 导师在组会上最常从哪里下手
* 过去真实出现过哪些批评、追问和打断
* 哪些回应有效，哪些回应会让局面更糟

## 提取维度

### 1. 高压场景

* 最常见的组会/汇报类型
* 用户最容易失控的时刻
* 导师最常在哪个节点打断

### 2. 高频批评

* 最常被批的问题类型
* 导师的原话或近似表达
* 这些批评背后真正关注的是什么

### 3. 追问路径

* 导师通常怎么一步步往下问
* 是先问意义、定义、实验、工作量，还是先否定再细问
* 哪些问题会连环追问

### 4. 危险信号

* 哪类表述最容易引发不满
* 哪类准备不足会立刻暴露
* 用户最容易在哪些地方显得虚、散、乱

### 5. 有效应对经验

* 用户过去哪种回应比较有效
* 哪种回应会让导师继续追着打
* 有没有可复用的缓冲句、承接句、补救动作

### 6. 情绪触发点

* 用户一听到什么话会慌
* 是害怕被否定、害怕显得没做事，还是害怕细节答不上来
* 哪些恐惧来自真实漏洞，哪些来自过度放大

## 输出格式

```markdown
## 组会场景概览

## 高频批评库

## 追问路径

## 汇报危险信号

## 有效与无效应对

## 情绪触发点

## Correction 记录
```
